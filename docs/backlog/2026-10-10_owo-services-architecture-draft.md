# Черновик: архитектура owo с пререндером, API и UI

> Набросок, не решение. Вырос из `docs/backlog/2026-10-10_ssr-prerender-meta-scripts.md`.

## Компоненты

- **owo (Go)** — как сейчас: собирает страницы по текущим правилам (uploads, `.meta/`, шаблоны), отдаёт HTML и статику, ресайзит картинки. Новое: если для страницы есть готовый артефакт пререндера (снапшот / патч / `sizes`) — применяет его; при изменении uploads/`.meta/` публикует задачу в очередь.
- **prerender-воркер (Bun)** — отдельный сервис, читает задачи из очереди, гоняет страницу через headless Chrome (`Bun.WebView` или `chrome-headless-shell`) на наборе ширин, выполняет server-скрипты, снимает замеры, складывает артефакты. Заказывает прогрев кэша картинок под измеренные размеры.
- **API (Bun)** — библиотека shared-скриптов, привязка скриптов и их параметров к страницам/директориям, статус пререндера, ручной запуск пересборки.
- **web UI (Svelte SPA)** — интерфейс к API: пользовательская библиотека скриптов, подключение и настройка их на страницах, просмотр статуса пререндера.
- **Очередь** — связь Go → воркер. Кандидаты: Redis (+ BullMQ на стороне Bun), NATS, или минимальная очередь на SQLite/файлах, чтобы не тащить лишний сервис. Не выбрано.
- **Хранилище артефактов** — по умолчанию файловая система рядом с кэшем (`/var/www/owo/cache/prerender/...`), общий volume между Go и Bun-контейнерами; ключ — путь страницы + хэш HTML/скриптов.

## Опциональность и конфиг

Всё сверх текущего owo — опционально. Базовый owo без очереди, воркера, API и UI работает ровно как сейчас; если воркер упал или не настроен, Go просто отдаёт страницу без пререндера и клиентские скрипты выполняются как раньше (плюс фоллбэк из `docs/backlog/2026-10-10_client-side-prerender.md`).

Конфигурация через сервер, три источника с приоритетом: CLI-флаги > env (как сейчас `PORT`, `PUBLIC_DIR`) > файл (`owo.yaml` или `owo.json`) > дефолты. Набросок:

```yaml
prerender:
  enabled: false
  mode: headless        # headless | client | both
  viewports: [360, 768, 1280, 1920]
  queue: { driver: sqlite, url: ... }
  workerConcurrency: 1
api:
  enabled: false
  url: http://owo-api:4000
ui:
  enabled: false
```

## Открытые вопросы

- Какая очередь (см. выше) и кто владеет ей в docker-compose.
- Нужно ли Go вообще знать про API, или API ходит в Go/файлы сам, а Go только читает артефакты.
- Где живёт конфиг скриптов страниц — в `.meta/` (файлы, как сейчас, git-friendly) или в БД API.
- Авторизация UI/API (сейчас у owo её нет вообще).
